## Key Questions
1. Which trigger mutations are valid during context preparation, and when does the final trigger snapshot become immutable?
2. Which Pattern API best represents a main axis, spawn origin, and per-shot modifiers without reintroducing mutable contexts?
3. Should Brimstone's per-step Pattern return one context or a small runtime shot descriptor containing a context plus laser-only metadata?
4. Which pipeline modes remain public after callers are migrated to semantic request factories?

## Decisions Made
| Decision | Rationale |
|----------|-----------|
| Use a Builder/factory for common context construction | Keeps required parameters explicit while eliminating repeated default resolution across attack types. |
| Resolve damage, range, and speed at context creation | Makes each projectile's behavior stable and avoids delayed owner-attribute changes. |
| Sanitize invalid range/speed instead of throwing | A malformed effect must not frequently crash the game; the resulting Context must still contain valid values. |
| Drive ordinary spread and Brimstone generation through AttackPattern | Patterns express main-axis plus per-shot geometry and avoid mutating an existing Context. |
| Create fresh Brimstone contexts per firing step | This is cheap at the expected shot count and preserves following the current shooter direction. |
| Keep sequenceIndex out of AttackContext | It is laser/Brimstone runtime state, not a universal projectile-construction property. |
| Preserve intentional CompositeTrigger access, but define lifecycle boundaries | Existing bullets and effects consume triggers, while parent/child isolation requires snapshots and controlled mutation timing. |
| Treat pipeline cleanup as a separate phase | Manual event dispatch and mode semantics should be changed after Context and Pattern contracts stabilize. |
