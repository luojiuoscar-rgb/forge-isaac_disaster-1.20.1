# 蓝苍蝇模型源文件

`blue_fly.bbmodel` 是已确认的 Blockbench 外观源文件，内嵌原始贴图和动画参考。
此目录不进入模组运行资源；Minecraft 使用 Java 模型、静态 PNG 和客户端公式动画。
`blockbench` 随仓库保存可编辑美术源文件，避免源模型仅留在临时目录或某次 Blockbench 会话中。
重新编辑模型时直接打开此文件；游戏不会自动读取 `.bbmodel`，修改后需要同步 Java 模型与运行贴图。

- `entity/familiar/impl/fly/AbstractFlyFamiliarEntity`：共用环绕、追击、归位、绕障和接触消耗行为，继承玩家跟班的归属、有效性检查和清理规则。
- `entity/familiar/impl/fly/BlueFlyEntity`：主体固定为 `#4077E0`，接触伤害读取主人当前 `attack_damage`，没有额外接触效果或自然生成。
- `client/model/creature/FlyModel`：所有兼容苍蝇共享的几何、八次每秒的扇翅和轻微起伏。
- `client/renderer/creature/FlyRenderer`：通用渲染器，仅给身体染色，保留翅膀原色、原版光照和透明像素裁切。
- `textures/entity/creature/fly.png`：16×16 静态共享贴图，身体区域为白色以接受 RGB 染色；翼色与翅根开口保留定稿效果。

添加同形状的苍蝇跟班时，继承 `AbstractFlyFamiliarEntity`，实现 `getBodyColor()`、`getContactDamage(owner, target)`
和 `onContactHit(owner, target, hitPosition, attemptedDamage, damageAccepted)`，
注册实体类型及同名跟班描述，并将实体关联到共享 `FlyRenderer` 即可。无需重建模型、复制动画或另画贴图。
`tickFamiliar()` 为最终共用流程，子类不需要重写。接触时先扣除需求并解除 UUID 登记，再尝试伤害，
避免伤害事件回调修改跟班后重复扣数；实体保留到伤害结算结束，在 `finally` 中销毁并退出攻击队列。
`onContactHit()` 接触效果仍在伤害尝试与实体清理完成后调用；
盾牌或伤害事件阻止伤害时也消耗一次苍蝇，`damageAccepted` 表示原版 `hurt()` 返回值，不等同于最终扣血数。
当前模型与渲染器直接接受苍蝇跟班基类；未来引入敌对苍蝇时，再按实际需求设计外观复用。
各类型提供固定的基础颜色；客户端根据观察者与主人关系计算闪烁，不修改实体的基础颜色或增加网络同步。
主人为本地玩家本人或同一队伍成员时保持本色；其他已识别主人的苍蝇主体在本色和浅灰白色（`#D8D8D8`）间直接切换，
每秒 8 个完整循环，本色和浅灰白色各持续 62.5 毫秒。使用客户端时钟，翅膀保持原色；主人暂不可识别时使用本色。

身体为 2×2×2 模型单位（0.125 格），翅膀为 3×0×2。模型逻辑 UV 尺寸为 8×8，
实际 PNG 为 16×16，所以每模型单位对应两个贴图像素；贴图分辨率不改变几何大小。
两片翅膀分别只生成上下两个面，整个模型共十个四边形。使用带背面剔除的实体裁切渲染，避免重叠双面重复绘制。

原版盒式 UV 与 Blockbench 自由格式逐面 UV 不同；不要直接覆盖运行 PNG。
模型部件名为 `fly_root`、`body`、`wing_left`、`wing_right`，转轴在翅根。
翅膀静止时向两侧平直展开，没有水平方向的向后偏转；飞行时保留上下扇动。
Blockbench 动画作为调节参考保存，游戏中的动画由 `FlyModel.setupAnim` 计算。
源文件仍内嵌蓝色外观预览；运行贴图的白色身体由渲染器染回蓝色，不应直接用源文件内嵌贴图覆盖。

游戏中使用：

```mcfunction
/isd familiar @s add isaac_disaster:blue_fly 1
```

可用 F3+B 查看实体身体碰撞箱。实际尺寸很小，建议近距离查看。
测试结束后使用 `/isd familiar @s remove isaac_disaster:blue_fly 1` 减少需求并清理实体。
蓝苍蝇实体不单独存档，由玩家保存的跟班需求重新生成。直接 `/summon` 的无主苍蝇会在 20～40 tick 内被清理。
仅移除实体而不减少需求时，跟班系统会补生；正常接触攻击会同时减少需求，不会补生。
同维度内，所有跟班离主人超过 16 格时暂停行为并排入玩家的运行时召回队列。
调度器优先逐只传送回主人约 55% 高度处，保留原实体、UUID、登记顺序及需求数量，清除旧攻击与导航状态。
召回和新生成共用每位玩家每 tick 一个的入场额度，重复调用不会增加额度；待召回实体不会被周期维护误删。
跨维度或区块卸载后找不到实体时仍保留清理登记及补生兜底；旧实体重新更新时若已失去登记，会被清理。
召回队列及额度不存档，玩家存档仍只保留跟班需求；召回不会误算为攻击消耗。

## 共用飞行行为

- 所有苍蝇类型共用等角圆环，身体中心在玩家实际碰撞箱高度 50% 处。普通体型半径 2.1 格；
  随玩家宽度增大，缩小时保留容量下限。至少为 64 只预留间距，更多类型的苍蝇合计超过 64 时仍可扩圈。
- 稳定环绕和随机游飞使用每 tick 0.3 格的移动预算，进攻队首使用 0.5 格，跟随队列与归队最高 0.6 格；
  所有自主飞行的速度上限均为 0.6 格/tick，不叠加玩家速度；路径终点或受阻时可不足当前预算。
- 玩家中心 8 格内自动索敌，每位玩家每 4 tick 共享一次候选扫描。敌意怪物优先，随后是其他敌人、
  正在威胁主人的非动物中立生物及符合 PVP 规则的玩家；动物、村民和友方不主动攻击。
  同一 tick 的目标资格判断按玩家共享，死亡和移除立即排除，真正接触伤害前再次实时检查目标资格。
- 同一玩家的苍蝇共用一条进攻队列，每位玩家每 tick 最多新加入一只，包含首次成为队首的苍蝇。
  新一轮攻击选定目标后，由距离该目标最近的苍蝇担任队首；距离相同时按共享圆环登记顺序选择。
  仅在首次组队时比较距离，已有队列保持原有接续顺序。
  从队首在共享圆环中的编号递减选取，例如 19、18、17，编号 1 之后回到末尾；
  该顺序沿视觉环绕队形向后展开。自动加入候选处于 `ROAM` 或 `CHASE` 时跳过。
  尚未加入者继续环绕或归位。队列使用同一目标，保持目标直到失效或离开范围；攻击苍蝇保留原编队槽位。
  队首消耗、队列暂时为空时仍保留下一候选顺序，同 tick 不额外补入新队首。
- 只有队首使用半格三维 A*，排序采用 `g + 1.5h`。每次请求最多 2048 节点，每位玩家每 tick
  最多提供一次 512 节点额度，保留搜索进度跨 tick 推进，耗尽上限需要四 tick；重新规划冷却仍为 10 tick。
  只有邻近目标的节点尝试直连终点，已有路线或搜索期间不反复检查整段直线路径；跟随者不重复寻路。
  查询不加载新区块，实际移动逐段检查身体碰撞。
- `FlyAttackQueue` 保存队列、目标及唯一规划器，`FlyAttackTrail` 保存队首实际走过的世界坐标轨迹。
  跟随者沿轨迹前进，按前一只的轨迹进度保留 0.3 格间隔；接入轨迹被挡住时允许停留。
  队首消耗或失去登记后，下一只继任并继续已有轨迹，目标失效后整队重新索敌或归队。
  已通过的轨迹按队尾进度释放，最多保留 256 个轨迹点；这些数据只在运行时存在，不存档。
- 环绕路径受方块阻挡时立即进入 `ROAM`：在主人腰部附近选择可直达的随机位置游飞，
  保留身体碰撞检查，不继续反复冲向墙外的槽位。游飞持续 40～80 tick 后重试归队；索敌仍运行，发现目标立即追击。
  完整槽位路径每 4 tick 检查一次，实际位移受阻则立即转为游飞。游飞复用已验证目标，途中受阻后等待 10 tick 再选点。
- 普通体型游飞水平半径约 2 格，随主人宽度变化，范围为 0.75～3 格；竖直目标位于腰部上下约 0.9 格，
  随实际高度变化，半高范围为 0.3～1.25 格。优先选择有明显高度差的目标，低矮空间中允许放宽高度偏好；
  所有候选位置及到达路径都通过实际身体碰撞检查，墙壁和天花板会缩小可用范围。
- 玩家体型过大、正常圆环槽位超出 16 格回收范围时，直接改为近身游飞，避免反复飞出范围后补生。
- 环绕不再搜索附近替代槽位，也不为归队单独规划绕障路线。目标不可达时整队暂时排除该目标 20 tick；
  连局部游飞位置都无法找到时安全悬停。允许重叠和卡住，不执行苍蝇间排斥或位置预约。
- 跟班伤害类型为 `isaac_disaster:familiar`，绕过受击无敌帧且不造成击退，保留护甲、抗性与盾牌处理。
- 客户端只插值服务端位置与旋转，继续播放现有扇翅动画，不自行索敌或结算伤害。
- 苍蝇距离摄像机 32 格内可渲染，沿用视锥裁剪；该阈值不依赖小碰撞箱的原版距离缩放。
  服务端追踪范围为 48 格（`clientTrackingRange(3)`），位置更新间隔保持 1 tick；距离主人的 16 格召回规则独立生效。

## 数量上限、共享配额与编号

注册描述提供 `limit`（单类型生效上限）、可选限额组引用、`priority`（同组竞争优先级，默认 0）
和 `retainOverflow`（默认 false）。组使用独立的 Forge 自定义注册表 `isaac_disaster:familiar_limit_group`；
每个组只描述共享上限，每种类型最多引用一个组。玩家 capability 创建时为全部已注册组提前创建独立的
`FamiliarLimitGroupInstance`，实例内部用 `Map<ResourceLocation, Integer>` 保存各类型占用量。

蓝苍蝇的注册为：

```java
new FamiliarEntityType(ModEntities.BLUE_FLY, 64, ModFamiliarLimitGroups.FLIES, 0, false)
```

其他颜色苍蝇引用同一个 `ModFamiliarLimitGroups.FLIES`，即与蓝苍蝇共用 64 份额度；
同时仍可设置自身更低的 `limit`。菜刀目前无数量上限、无共享组，并设置 `retainOverflow=true`。

- `FamiliarEntry.getCount()` / `PlayerFamiliarData.getCount(type)` 返回记录数量，供增减、反馈和存档使用；读取不修改数量。
- `PlayerFamiliarData.getEffectiveCount(type)` 返回生效配额，是补生和超额清理的目标。
  无组类型直接取记录数量与自身上限的较小值；有组类型从玩家的组实例 Map 中读取，没有第二份条目级配额副本。
- `FamiliarEntry.getEntityCount()` 返回当前实际登记的实体数量；逐只生成、区块卸载或补生期间可能少于配额。
- 修改需求时立即分配或释放共享额度，同优先级先到先得，后来者不能替换已有配额。
  例如先追加 64 只蓝苍蝇占满组后，同优先级其他颜色不会取得额度；不再等待生成时交替分配。
- 高优先级可以立即替换较低优先级。优先让最低优先级、较晚登记的类型让出配额，实际实体从 UUID 登记列表末尾清理。
  普通数量减少会减少记录；被替换则先释放配额，仅 `retainOverflow=false` 的类型同时减少记录数量。
- `retainOverflow=false` 丢弃单类型超额及不能取得组配额的数量；`true` 保留完整记录，未生效的部分等待。
  上限 13 时，记录 `20→15→12` 对应生效 `13→13→12`。普通减少先消减尚未生效的部分，
  释放额度后等待者按优先级、同级按条目登记顺序取得额度。数量算术限制在 `0…Integer.MAX_VALUE`。
- 生成器只按生效数量补齐实体，不再预留、提交或回滚配额。生成失败或加入世界被取消时清理新 UUID 和实体，
  新配额继续保留等待重试；已经发生的替换不撤销，已丢弃的旧记录不恢复。
- 调度器在召回或生成前清理超出配额的实体并取消其召回记录，静默清理不执行接触效果。
  常规召回和新生成仍每位玩家每 tick 共用一次机会；公开 `spawnNextMissingFamiliar` 由调用者控制调用频率。
  生成实体仍逐类型轮询补齐，这个顺序不再影响配额归属。
- 召回、临时失去实体和补生不释放或重复取得配额。存档仅保存有序的 Type + Count；
  组实例及占用量、UUID、召回队列和生成游标不保存。读档或复制时按优先级和条目顺序重建配额。
  条目完全删除后再添加，视为新的登记顺序。

`PlayerFamiliarData` 是数量修改入口，`FamiliarLimitGroupInstance` 在需求变化时更新组内配额，
`FamiliarHelper` 按期望数量生成、召回和清理世界实体；生成阶段不再进行组内竞争或配额重分配。
苍蝇与菜刀一样拥有类型内 `formationIndex`；圆环另按同一主人的所有苍蝇分配统一槽位。
编号随实体增减整理，不是永久身份；永久区分实体仍使用 UUID。

## 伤害来源与击退

`ModDamageSources` 统一构造 tear、laser、familiar 来源并保留各自伤害类型和归属；
tear 携带命中时不可变的速度快照，不为伤害归属创建假实体。
`HurtKnockback` 仅在一次 `hurt → knockback` 调用期间保存上下文，匹配受击实体并只能消费一次，
通过 `try/finally` 恢复，支持嵌套伤害和异常退出。

`LivingEntityKnockbackMixin` 独立承载三个击退钩子，保留 MixinExtras 调用链和原有来源上下文处理；
`LivingEntityMixin` 保留冻结、摩擦和缩放等逻辑。三类来源均完整分发 `LivingKnockBackEvent`：

- Tear 以 0.10 基础强度和子弹水平推进方向进入事件，采用事件修改后的强度与方向并应用击退抗性；
  只增加水平速度，保持原竖直速度，跳过原版的额外抬升。事件取消、冻结和神圣护盾仍可阻止推力。
- Laser、familiar 以零强度进入事件，分发后不执行原版击退，即使监听器增大事件强度也不主动推动。
- 其他伤害完整使用原版处理；不保留 UUID 待处理击退表，也不需要 tick 末清理。

菜刀继续使用自己的攻击伤害类型。护甲、抗性、盾牌和苍蝇接触后无论伤害是否成功都消耗一次的规则保持原样。
主体染色计算已合并到 `FlyRenderer`，保持当前浅灰白闪烁和翅膀原色。

All AbstractFlyFamiliarEntity variants share orbiting, following, the same attack
queue, contact consumption and hostile-view flashing. Different colors can lead
and join one mixed queue. Variants supply getBodyColor(), getContactDamage() and
onContactHit(); BlueFlyEntity only defines its color, panel damage and empty effect.
TrackingTargetRules.eligibleFlyOrSpider supplies the shared target policy for
both fly and spider families.
